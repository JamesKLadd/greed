# Phase 4A + 4B checkpoint

Table detail polish, local setup, and shared match results are implemented.
The table composition and seat coordinates remain unchanged. This checkpoint
stays on `codex/challenge-gameplay-polish`; it does not deploy to main or make
the visual beta the default. The existing beta gate, release version, scoring,
challenge allowances, earned progression, and online authority are preserved.

## Table details — 4A

- The turn name and points at risk have separate space in a compact row.
  Resolved bank/bust/game-over states show zero points at risk, even while the
  engine retains the previous hand for its result display. Bank's secondary
  score follows the same rule in both table presentations.
- All hot dice retain their held indicators until a fresh five actually starts
  rolling. Releasing some of that hand immediately follows the engine's held
  selection. Tapping the last held die gives a visible rule explanation in the
  existing guidance area; it does not change the rule or post a move.
- A small arrow identifies the active seat without relying on a glow alone.
  Numeric team markers pair with consistent Amber/Teal colors. Long names stay
  inside their existing plaques; tapping a name or character reveals the full
  name, banked total, team total, current turn, final-seat status, and presence.
  Accessible button names carry the same information.
- Scores fit their existing slots, including translated number formatting and
  large text. The final-seat flag has a static outline during the final round,
  including reduced-motion mode. Disconnected nameplates have a dashed border.
- The start-of-turn clock fits inside the turn row, and the row clears the
  viewer's score on short phones and landscape layouts. Dice, characters,
  action buttons, camera placement, turn order, and the blank footer keep their
  existing geometry.

## Local setup — 4B

Setup uses clear seat cards: one column on phones and two on desktop. Name
fields, Human/Bot controls, bot temperament, team selection, add/remove actions,
and goal choices have at least 44px control height. Start has a larger 52px
target. Selected choices expose pressed state; unavailable actions explain
the 2-player minimum, 8-player maximum, and 4/6-player team requirement.

Bot temperament is explicitly separated from skill. Unbalanced teams block
Start and offer one action to even the sides. Custom goals remain editable as
text during typing, then normalize on blur and Start to steps of 50 within
500–100,000 points. Empty/invalid input falls back to the existing 3,000-point
default. This also handles starting while the field still has focus.

Inputs use a numeric keyboard hint for goals and Done for names/goals. Enter
blurs the field. Controls remain in document flow rather than floating over a
phone keyboard. Actual mobile keyboard behavior still needs device testing.

## Match results — 4B

The shared results card shows the winning score before standings. Known own
rows are labelled; competition ranks preserve equal totals. Team totals and
individual contributions are distinct. Personal summaries appear only when
provided and add the player's final total beside best turn, hot dice, and busts.
Numbers follow the selected locale, and long names wrap without displacing
scores. Shared setup/results readability changes also apply to Classic.

The primary replay/rematch action stands out. Chosen votes expose pressed
state and explain how to cancel. Host lobby, leave, waiting, local replay, and
spectator actions retain their existing callbacks and permissions. Result
actions have at least 48px height. The terminal modal remains nondismissible
and scrolls to all standings, unlocks, and actions.
